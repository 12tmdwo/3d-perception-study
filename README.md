# 3d-perception-study

## 물체 3D 스캔: 진행 기록

손에 든 이동 카메라로 물체를 여러 방향에서 찍어 3D 점군을 만드는 프로젝트다. 고정 카메라 1대가 좌표계 기준을 잡고, Depth Anything 3(DA3)로 깊이와 카메라 위치를, YOLO로 물체 영역을 구한다.

### 공통 구성

| 항목 | 내용 |
|---|---|
| 컴퓨터 | GTX 1650 Max-Q (메모리 4GB), i5-8265U |
| 카메라 | Logitech C270 2대, 640×480. 두 대의 일련번호가 같아 USB 자리(`/dev/v4l/by-path`)로 구별 |
| 고정 카메라 | USB 1.1 자리, 캘리브레이션 `code/calibration/camera_params1.npz` |
| 이동 카메라 | USB 3 자리, 캘리브레이션 `code/calibration/camera_params.npz` |
| 물체 영역 | YOLO26n-seg TensorRT 엔진(`yolo26n-seg.engine`), 한 장 15~33ms |
| 깊이·위치 | DA3-SMALL, 두 장 217ms (fp32) |
| 미터 눈금 | DA3METRIC-LARGE, 한 장 666ms |
| 정밀도 | fp32 고정. 이 그래픽카드에서는 bf16이 약 1.5배, fp16이 약 2배 느림 |
| 왜곡 보정 | 사용 안 함. 기존 왜곡 계수가 C270 가장자리를 지나치게 보정함 |

코드: `code/scan/scan_live.py` (실시간 스캔), `code/scan/two_view_check.py` (두 장 검증), `code/scan/bench_da3.py` (속도 측정)

### Version 1: 고정 카메라 기준으로 점군 쌓기

**방식**
1. 시작할 때 고정 카메라로 사람 없는 기준 사진을 한 장 찍고, DA3METRIC으로 기준 사진의 미터 깊이를 구한다.
2. 이동 카메라 사진마다 `[기준 사진, 지금 사진]`을 DA3-SMALL에 넣어 이동 카메라 위치를 구한다.
3. 크기 눈금 `s` = 중앙값(기준 사진 미터 깊이 / DA3 깊이)으로 미터 단위로 바꾼다.
4. YOLO 마스크 안의 물체 점만 3D로 바꿔 고정 카메라 좌표에 쌓는다.

#### 문제 1. 물체 테두리 뒤로 점이 꼬리처럼 늘어짐
- **추정 원인:** 테두리 픽셀의 깊이가 앞 물체와 뒤 배경 사이 값으로 섞인다. 마스크 가장자리를 4px 깎아도 DA3 처리 크기(504×378)로 줄이면 약 3px밖에 안 깎인다.
- **해결:** 마스크 가장자리 깎기를 4px → 10px로 늘림 (`--erode 10`)
- **결과:** 꼬리가 거의 사라짐 (실시간 시험에서 눈으로 확인)

#### 문제 2. 키보드를 찍었더니 겹이 번지고 이동 카메라 경로가 튐
- **분석 방법:** 40초 녹화 2개(초당 약 28장)를 프레임마다 분석

| 측정 | 녹화 A | 녹화 B |
|---|---|---|
| 가만히 있을 때 위치 흔들림 | 22.1mm | 27.6mm |
| 가만히 있을 때 회전 흔들림 | 4.30° | 4.78° |
| 가만히 있을 때 눈금 `s` 변동 | 1.3% | 1.0% |
| 움직일 때 0.1초 사이 최대 위치 변화 | 27.2cm | 91.1cm |
| 움직일 때 0.1초 사이 최대 회전 | 34.8° | 176.6° (뒤집힘) |

- **확인한 것:**
  - 흐린 사진과 튄 순간의 관련은 약했다.
  - `use_ray_pose`는 효과가 없었다 (23.4mm·5.01°, 두 배 느림).
  - **기준을 이동 카메라 첫 장**(방향 차이 약 1°)으로 바꾸면 흔들림이 **3.3~3.9mm·1.0~1.5°**로 줄었다.
- **추정 원인:** 고정 카메라와 이동 카메라의 **방향 차이가 약 80°**(거리 64~74cm)로 커서, DA3가 계산하는 회전이 매번 4~5°씩 흔들린다. 이 흔들림이 약 70cm 거리에 곱해져 위치가 2~3cm씩 튄다. 깊이 눈금은 안정적이었다.
- **해결:** Version 2(키프레임)로 넘어감

### Version 2: 키프레임 이어 붙이기

**방식**
1. 첫 프레임만 `[고정 카메라 기준 사진, 지금 사진]`으로 좌표계를 잡고, 그 사진을 첫 키프레임으로 삼는다.
2. 이후에는 `[최근 키프레임, 지금 사진]`으로 키프레임 대비 움직임을 구해, 키프레임 위치에 이어 붙인다.
3. 키프레임에서 **15° 넘게 돌거나 15cm 넘게 움직이면** 지금 사진을 새 키프레임으로 삼고, DA3METRIC으로 미터 깊이를 다시 구한다.

**방식 선택 근거** (Version 1 녹화로 비교)

| 방식 | 가만히 있을 때 흔들림 | 0.1초 사이 최대 위치 변화 | 20° 넘게 돈 횟수 | 1장당 시간 |
|---|---|---|---|---|
| Version 1 | 22.1~27.6mm, 4.3~4.8° | 27~91cm | 2~37회 | 235~240ms |
| 세 장 넣기 `[고정, 0.5초 전, 지금]` | 18.3~29.0mm, 4.0~5.3° | 8~42cm | 1~29회 | 368~376ms |
| **키프레임** | **3.3~3.9mm, 1.0~1.5°** | **3.7~10.3cm** | **0회** | 262~272ms |

**결과**
- 녹화 재생: 가만히 있을 때 흔들림 **1.1~2.8mm·0.16~0.81°**, 경로가 부드러움, 초당 3.4~3.8장
- 실제 시험에서는 **겉보기로 Version 1과 차이가 없었다.**

#### 문제. 움직일 때마다 키보드 모양이 조금씩 움직여 겹쳐 보임

- **처음 추정:** 거의 같은 사진 두 장이면 DA3가 회전을 틀리게 낸다.
  - 근거: 같은 사진 6장으로 만든 가짜 녹화에서 44.2mm·11.3° 어긋남
  - → **틀린 추정.** 직접 재 보니 같은 사진은 0.31~0.54°, 20px 민 사진은 1.53~1.75°로 정상이었다.
- **확인된 원인:** 같은 사진이라도 **DA3에 함께 넣는 짝 사진에 따라 깊이 모양이 달라진다.** 같은 사진 B의 물체 점군을 크기만 맞춰 `[B, B]`와 비교했다.

| 만든 방법 | 어긋난 거리 | 어긋난 각도 | 크기 차 |
|---|---|---|---|
| `[20px 민 B, B]` | 7.8~14.2mm | 1.5~4.5° | 1.3~4.1% |
| DA3-SMALL 한 장 | 18.2~32.9mm | 2.9~4.8° | 4.4~13.7% |
| `[고정 카메라, B]` | 44.2~81.4mm | 17.7~23.3° | 5.7~25.0% |
| DA3METRIC 한 장 | 50.3~103.1mm | 16.1~20.2° | 18.9~32.2% |

  - 첫 프레임은 짝이 고정 카메라라 모양이 약 20° 뒤틀린 겹이 쌓인다.
  - 키프레임이 바뀔 때마다 짝이 바뀌어 겹 모양이 조금씩 달라진다.
  - **초점거리는 원인이 아니었다.** DA3 추정 초점거리를 쓰면 가짜 녹화에서 89.2mm·13.0°로 오히려 나빠졌다.
- **해결:** Version 3(ICP로 맞춰 쌓기)으로 넘어감
- **기타:** 재부팅 때 `/tmp`에 저장한 녹화가 지워져, 진단 도구와 녹화를 `~/scan_debug`로 옮김

### Version 3: ICP로 맞춰 쌓기 (현재)

**방식** (Version 2에 추가)
1. 첫 프레임(짝 = 고정 카메라) 점은 **쌓지 않고** 좌표계만 잡는다.
2. 새 물체 점을 이미 쌓인 점군에 **ICP(이동·회전·크기)로 맞춘 뒤** 쌓는다. 3cm 안에서 짝 점을 찾는다.
3. 겹침 비율이 0.3 미만이거나 보정이 30mm·10°를 넘으면 그 프레임은 버리고, 키프레임으로도 삼지 않는다.
4. ICP 보정을 이동 카메라 위치에도 반영한다.
5. Mask 창 두 번째 줄에 ICP 보정량(mm, °, 크기 %, 겹침 비율)을 표시한다.

**결과**
- 자체 검사: 가짜 면을 5° 돌리고, 3% 키우고, 1cm 옮긴 것을 ICP가 되돌림
- 가짜 녹화(같은 사진 6장): 어긋남 44.2mm·11.3° → **0.0mm·0.0°**
- 실제 촬영에서의 효과는 **확인 전**

**알려진 한계**
- 먼저 쌓인 겹이 틀리면 그 모양을 따라간다.
- 새로 보이는 면은 쌓인 점과 겹치는 부분이 적어 맞출 근거가 약하다.
- 짝 사진에 따라 모양이 달라지는 원인 자체를 없애는 것이 아니라, 생긴 어긋남을 줄이는 방식이다.

### 다음 계획
1. Version 3의 ICP 효과를 실제 카메라로 직접 확인한다.
2. 효과가 좋으면 실시간 방식을 계속 발전시킨다.
3. 효과가 부족하면 **작업 공간에 ArUco 마커**를 놓고 위치를 구한다.
4. 그래도 부족하면 **실시간을 포기**하고 스페이스로 사진을 찍는 방식으로 바꾼다.
